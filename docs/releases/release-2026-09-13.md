## Follow-up: automatic browser save retries — September 14

The browser no longer displays **Retry saving session**. Ending a conversation
automatically finalizes pending recording data, saves the session, and retries
transient end/upload/manifest failures up to three times using the identical queued
payload. The second and third attempts wait 750 ms and 2 seconds. A successful save
continues directly to feedback; exhausted attempts or incomplete data display an
accessible persistent note and do not request evaluation.

Deployment `ad876ef1-c28e-47b3-8971-9b79d10624f1` completed successfully. The
release passed 207 backend tests, 43 browser tests and a headless Chrome test that
failed the first two audio uploads, saved the third identical attempt and rendered
feedback exactly once. The signed-in hosted page confirms that the retry control is
absent, the failure-note region is present and initially hidden, the automatic-save
copy is visible, and the browser console has no warnings or errors.

## Follow-up: concise speech feedback — September 14

The practice page replaces the raw turn-by-turn Azure Speech dump with one concise
paragraph. It reports arithmetic mean pronunciation, spoken-fluency and available
prosody scores across assessed passages, identifies the strongest and weakest area
when their scores differ by at least five points, and lists at most three
lowest-scoring flagged words to practice. It summarizes unavailable or insufficient
recordings without showing transcripts, timestamps, individual word scores or
phonemes. The detailed evidence remains unchanged in the evaluation API.

## Follow-up: unified coaching report — September 14

The evaluator now treats Azure Speech as the measurement source and the existing
Azure OpenAI text model as the single report writer. Rubric `unified-coaching-v3`
adds deterministic coverage, segment-average metrics and up to three flagged words
to the compact Speech context. The model must combine those findings with grammar,
vocabulary and coherence into one short summary, one to three strengths and one to
three ranked priorities. It cannot emit a separate pronunciation report, infer
acoustic issues from transcripts or present the application averages as certified
proficiency or Azure whole-session scores.

The browser now renders **Overall feedback**, category evidence, **Strengths**,
**Top priorities** and any grounded **Corrections**. It no longer loads or displays
the separate speech-summary module. Detailed per-turn Speech measurements remain in
the evaluation API. Completed evaluations retain their saved rubric and report;
fresh conversations use the unified rubric.

Deployment `217e68d9-d31b-4a5e-8cf9-0116a112767a` completed successfully. Verification
passed with 206 backend tests, 41 browser tests, JavaScript syntax checks, Markdown
link validation, package inspection and a headless Chrome automatic-save/feedback
smoke test. The cache-busted signed-in page loaded the four expected browser modules
without the old speech-summary module, and its browser console had no warnings or
errors.
